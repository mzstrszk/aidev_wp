# ADR-002: レイアウト実現方法の判断

## ステータス

承認済み

## コンテキスト

Figma のデザインを WordPress ブロックテーマとして実装する際、
すべてのレイアウトをコアブロックだけで再現できるとは限らない。
コアブロックで対応する範囲と、カスタム CSS やカスタムブロックに頼る範囲を決める必要がある。

## 決定

以下の優先順位でレイアウトを実装する。

1. **theme.json の設定**（最優先）
   - カラー、フォント、スペーシング、レイアウト幅はすべて theme.json で制御
2. **コアブロックの組み合わせ**
   - Group, Columns, Cover, Query Loop 等を組み合わせてレイアウトを構築
   - ブロックの `align`, `layout`, `spacing` 属性を活用
3. **theme.json の `styles.blocks` によるブロックスタイルのカスタマイズ**
   - 特定のコアブロックのデフォルトスタイルを theme.json で上書き
4. **追加 CSS（`assets/css/`）**（最終手段）
   - 疑似要素（`::before`, `::after`）、アニメーション、複雑なホバー効果のみ
   - 使用する場合は ADR-004 に理由を記録する
5. **カスタムブロック**（原則不採用）
   - コアブロックでどうしても実現できない場合のみ検討
   - 導入する場合は別途 ADR を作成する

## 選択肢

| 選択肢 | メリット | デメリット |
|---|---|---|
| A: コアブロック + theme.json 最大活用（採用） | サイトエディタとの完全互換。保守が容易。WordPress のアップデートに追従しやすい | Figma のデザインを 100% 再現できない場合がある |
| B: コアブロック + 大量のカスタム CSS | デザイン再現度が高い | サイトエディタでの編集と CSS が競合するリスク。保守コスト増 |
| C: カスタムブロック中心 | 自由度が最大 | 開発コストが大きい。WordPress 本体の更新に追従する保守負担 |

## 結果

- Figma のデザインがコアブロックで再現できない場合、**デザイン側を調整する**ことを先に検討する
- 具体的に再現できなかった箇所とその対応は、Phase 4〜5 の作業中に本 ADR に追記する
- カスタム CSS を使用する場合は ADR-004 に記録する
