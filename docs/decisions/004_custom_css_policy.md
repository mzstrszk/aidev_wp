# ADR-004: カスタム CSS の使用方針

## ステータス

承認済み

## コンテキスト

このプロジェクトでは theme.json とコアブロックを最大限活用する方針だが（ADR-002 参照）、
theme.json だけでは実現できないスタイルが出てくる可能性がある。
カスタム CSS をどのような場合に許可し、どこに配置するかを決める必要がある。

## 決定

以下の場合に限り、`assets/css/` にカスタム CSS を追加することを許可する。

### 許可するケース

1. **疑似要素**（`::before`, `::after`）を使った装飾
   - 例: セクション間の斜めの区切り線、アイコンの装飾
2. **アニメーション・トランジション**
   - 例: ホバー時のフェード、スクロール時のフェードイン
3. **theme.json の `styles.blocks` では対応できない複雑なセレクタ**
   - 例: 特定コンテキストでのネストされた要素のスタイル
4. **印刷用スタイル**（`@media print`）

### 禁止するケース

- カラー、フォントサイズ、スペーシングの直接指定（→ theme.json プリセットを使う）
- レイアウト（幅、配置）の制御（→ ブロック属性と theme.json の layout を使う）
- コアブロックのデフォルトスタイルの上書き（→ theme.json の `styles.blocks` を使う）
- `!important` の使用（やむを得ない場合はこの ADR の末尾に理由を追記）

### 配置ルール

- ファイル名: `assets/css/custom-{機能名}.css`（例: `custom-animations.css`）
- functions.php の `wp_enqueue_style` で読み込む
- CSS 内でも theme.json のカスタムプロパティ（`var(--wp--preset--color--xxx)` 等）を使用する

## 選択肢

| 選択肢 | メリット | デメリット |
|---|---|---|
| A: 条件付きで許可（採用） | 現実的。コアブロックの限界を補える | ルールを守る自律が必要 |
| B: 一切禁止（theme.json のみ） | 一貫性が最大。保守が最も容易 | デザインの再現度が下がる。複雑なインタラクションが不可 |
| C: 自由に使用 | デザイン再現度が最大 | サイトエディタとの競合リスク。theme.json 優先の方針が形骸化 |

## 結果

- カスタム CSS の使用はこの ADR で管理する（下記のログに追記していく）
- 06_refactor_to_tokens のリファクタリング時に、不要になった CSS がないか再確認する
- theme.json でスタイル可能な箇所にカスタム CSS が使われていた場合は、リファクタリング対象とする
