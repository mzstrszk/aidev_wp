# ADR-003: パターンの粒度の判断

## ステータス

承認済み

## コンテキスト

ブロックパターンをどの粒度で切り出すかを決める必要がある。
粒度が細かすぎると管理が煩雑になり、粗すぎると再利用性が下がる。
また、サイトエディタでユーザーがパターンを選ぶ際の使いやすさも考慮が必要。

## 決定

**セクション単位**をパターンの基本粒度とする。

具体的には:
- 1 パターン = 画面の横幅いっぱい（またはコンテンツ幅）の 1 セクション
- ヘッダー・フッターは**テンプレートパーツ**（`parts/`）として管理し、パターンにはしない
- ボタン単体やカード単体のような小さなコンポーネントはパターンにしない（コアブロックで十分）
- セクション内にサブパターンが必要になるほど複雑な場合は、セクション自体を分割する

### パターンカテゴリの方針

| カテゴリ | 内容 | 例 |
|---|---|---|
| `featured` | ページ上部の目立つセクション | ヒーロー、メインビジュアル |
| `call-to-action` | ユーザーの行動を促すセクション | CTA バナー、お問い合わせ誘導 |
| `text` | テキスト中心の情報セクション | 特徴紹介、サービス説明 |
| `query` | 投稿一覧を含むセクション | 最新記事、関連記事 |
| `{テーマ固有カテゴリ}` | 上記に収まらないもの | functions.php で登録 |

## 選択肢

| 選択肢 | メリット | デメリット |
|---|---|---|
| A: セクション単位（採用） | 直感的。Figma のセクション分けと対応しやすい | 一部のセクションが大きくなりすぎる場合がある |
| B: コンポーネント単位（ボタン、カード等も含む） | 再利用性が最大 | パターン数が膨大になる。ユーザーの選択肢が多すぎる |
| C: ページ単位（1 ページ = 1 パターン） | 管理が簡単 | 再利用できない。テンプレートとパターンの役割が重複 |

## 結果

- Figma のセクション区切りがそのままパターンの区切りになるため、デザイナーとの認識を合わせやすい
- パターン数の目安は 5〜15 個程度（多すぎる場合はカテゴリで整理）
- テンプレートは `<!-- wp:pattern -->` の呼び出し列になり、見通しが良くなる
